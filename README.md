# Фид для SearchBooster (ИНСКЛАД)

Tilda не включает товары с остатком 0 в свой YML, поэтому в умном поиске их нет.
Этот проект собирает **объединённый YML**: берёт фид Tilda как есть и добавляет
недостающие товары из `feed-fb.csv` с `available="false"`.

## Что получается

- ~5046 офферов: ~4867 из Tilda + ~179 отсутствующих (нулевой остаток).
- Отсутствующие помечены `available="false"` и заполнены **так же, как товары
  в наличии**: название, описание, все фото, характеристики (`param`), вес,
  категория, цена, ссылка. Данные берутся с публичной страницы товара.
- Существующие офферы Tilda не изменяются.
- Фид пересобирается автоматически раз в час, ссылка не меняется.

## Откуда берутся характеристики

`feed-fb.csv` не содержит характеристик и всех фото, поэтому для добавленных
товаров скрипт читает публичную страницу товара (`var product = {...}`) и
переносит оттуда `characteristics`, `gallery`, `pack_m` и описание. Токен Tilda
не нужен — страницы открыты.

Результат кэшируется в `feed/enrich-cache.json`, который коммитится в репозиторий:
повторно скачиваются только новые товары (0–5 страниц в час вместо 179). Если
страница недоступна, товар добавляется по данным CSV и дозаполняется при
следующем запуске.

## Публикация на GitHub Pages (бесплатно)

1. Создайте **публичный** репозиторий, например `insklad-feed`.
2. Загрузите в него содержимое этой папки (можно перетащить файлы в браузере):
   - `feed/build-feed.ps1`
   - `feed/enrich-cache.json` (если есть; иначе создастся сам)
   - `.github/workflows/feed.yml`
   - `.github/workflows/heartbeat.yml`
   - `README.md`
3. Откройте **Settings → Pages → Build and deployment → Source** и выберите
   **GitHub Actions**.
4. Откройте вкладку **Actions → Build product feed → Run workflow**
   (первый запуск вручную).
5. Через 1–2 минуты фид будет доступен по адресу:

   ```
   https://<ваш-логин>.github.io/insklad-feed/feed.xml
   ```

Эту ссылку нужно указать в SearchBooster как источник фида.

## Как обновляется

GitHub Actions запускается каждый час (`cron: "17 * * * *"`), заново скачивает
YML и CSV с сайта, собирает файл и публикует его по тому же URL.

`heartbeat.yml` раз в месяц делает коммит — это нужно, чтобы GitHub не отключил
запуск по расписанию после 60 дней без активности в репозитории. Тот же workflow
коммитит обновлённый `feed/enrich-cache.json`, поэтому он должен существовать в
репозитории (пустой `{}` допустим).

Логика идемпотентная (не «дописывание»):

| Событие в каталоге | Что происходит в фиде |
|---|---|
| товар закончился | Tilda убирает из YML → скрипт добавляет `available="false"` |
| товар снова в наличии | Tilda возвращает в YML → дубля нет |
| товар удалён/скрыт | пропадает из CSV → исчезает из фида |
| новый товар с нулём | появляется в CSV → добавляется автоматически |

## Проверка результата

```powershell
# сколько офферов и сколько out-of-stock
(Select-String -Path .\feed.xml -Pattern '<offer ' -AllMatches).Matches.Count
(Select-String -Path .\feed.xml -Pattern 'available="false"' -AllMatches).Matches.Count
```

Ожидаемо ~5046 и ~179. Затем в SearchBooster:

1. **Фиды с каталогом** → заменить ссылку на новый `feed.xml` (если кабинет не
   даёт менять ссылку — написать в поддержку).
2. Нажать **Обновить фид** и дождаться статуса «успешно обработан».
3. Проверить поиск по названию товара с нулевым остатком — должен находиться
   с пометкой «под заказ».

В скрипте есть защита: если YML или CSV скачались неполными, сборка падает и
GitHub Pages продолжает отдавать предыдущую рабочую версию.

## Вариант без GitHub: свой сервер

Если есть VPS/сервер с IIS или nginx:

1. Положите `build-feed.ps1` на сервер.
2. Создайте задачу в Планировщике заданий Windows (или cron):
   раз в час запускать
   `powershell -File C:\feed\build-feed.ps1 -OutPath C:\inetpub\wwwroot\feed.xml`.
3. Ссылка будет вида `https://ваш-домен/feed.xml`.

## Ручной запуск (локально)

```powershell
powershell -ExecutionPolicy Bypass -File .\feed\build-feed.ps1 -OutPath .\feed.xml
```

Требуется только Windows PowerShell 5.1+ (или PowerShell 7 на Linux/macOS).
